# 블라인드 / 금지 질문 규칙

> 다루는 것: 무엇을 어디서 거르는지, 규칙 파일의 모양, 기준이 바뀌었을 때 고치는 법, 한계.
>
> 상태: **지금 규칙은 임시 기준이다.** 현업(People팀)의 기준을 받기 전에, 채용 절차의 일반 원칙(채용절차법 제4조의3의 출신 지역·혼인 여부·재산·가족의 학력·직업·재산·신체 조건 등)을 참고해 만든 것이다. 기준 출처: 없음(현업 확인 전).

## 1. 무엇을 거르나

규칙 파일: `config/blind_rules.yaml` (버전 `draft-2026-11`).

| code | 이름 | 예 |
| --- | --- | --- |
| `gender` | 성별 | 성별, 남성/여성, "여자라서" |
| `age` | 나이 | 나이가, 몇 살, 95년생, 생년월일 |
| `family` | 가족 | 부모님, 아버지, 형제, 가족 관계, 가정 환경 |
| `marriage` | 결혼·출산 | 결혼, 기혼/미혼, 배우자, 임신, 출산, 육아, 자녀 |
| `origin` | 출신 지역 | 고향, 본적, 출신지, 사투리, 국적 |
| `religion` | 종교 | 종교, 교회, 성당, 신앙 |
| `politics` | 정치 | 정치 성향, 지지 정당, 노동조합 |
| `physical` | 신체 조건 | 몸무게, 외모, 혈액형, 병력, "키가 몇" |
| `property` | 재산 | 부동산, 월세, 전세로, 집안 형편 |

학교 이름, 병역, 사진, 장애, 성적 지향 등은 지금 규칙에 **없다.** 무엇을 더할지는 현업 기준에 따른다.

## 2. 어디서 거르나

`app/blind/filter.py`의 `BlindFilter`.

| 시점 | 무엇을 | 어떻게 |
| --- | --- | --- |
| 브리핑 입력 | 지원자 프로필(JSON) | 금지 키(`profile_keys`)는 값과 함께 지운다. 글 안에서 금지 항목이 든 **문장**을 `[블라인드 처리됨]`으로 바꾼다. 걸린 주제 코드는 응답의 `excluded`로 나간다 |
| 브리핑 출력 | 요약, 질문 | 금지 항목이 있으면 그 사실을 알려 주고 **한 번 다시 만든다.** 그래도 남으면 요약은 문장을 가리고 질문은 통째로 뺀다 |
| 꼬리질문 출력 | 후보 | 금지 항목이 든 후보는 내보내지 않는다 |
| 평가 출력 | 근거 설명, 총평 | 금지 항목이 든 문장을 가린다 |
| 보고서 출력 | 모든 글 | 금지 항목이 든 문장을 가린다 |
| 검수용 API | `POST /internal/v1/blind/check` | 글마다 걸린 주제·낱말을 돌려준다 |

- 백엔드가 주는 프로필은 이미 블라인드 제외본이다(API 명세 2.3). Agent의 입력 필터는 **한 번 더 거르는 안전망**이다.
- 프롬프트에도 금지 원칙 문장이 들어 있다(`app/prompts/common.py`의 `FAIRNESS`). 규칙 검사는 모델이 그 지시를 어겼을 때의 방어선이다.
- 거르지 않는 것: **실시간 전사와 보정 전사.** 지원자가 스스로 말한 내용은 기록이므로 그대로 둔다. JD 본문도 거르지 않는다.

`/internal/v1/blind/check` 응답(처음에는 이 레포가 정했고, 지금은 API 명세 4장에 있다):

```json
{ "clean": false, "rulesVersion": "draft-2026-11",
  "results": [ { "index": 0, "clean": false,
                 "violations": [ { "topic": "marriage", "label": "결혼·출산", "matched": "결혼", "ruleType": "keyword" } ] } ] }
```

## 3. 규칙 파일의 모양

```yaml
version: "draft-2026-11"
topics:
  - code: family                    # 응답에 나가는 값(영문). 이미 쓰는 값은 바꾸지 않는다
    label: 가족                     # 화면에 보이는 이름
    description: 가족 관계, 가족의 직업·학력·재산
    profile_keys: [family, 가족관계]       # 프로필에서 지울 키(대소문자 무시, 어느 깊이에 있든)
    keywords: [부모님, 아버지]             # 이 낱말이 있으면 걸린다
    patterns: ["가족\\s*(구성|사항)"]      # 정규식(파이썬 re)
    allow: [가족 같은]                     # 이 표현과 겹치면 무시한다
```

- 파일을 읽을 때 검사한다: `code`·`label` 누락, `code` 중복, 정규식 오류면 서버가 시작하지 않는다.
- 규칙은 서버 시작 때 한 번 읽는다. 바꾼 뒤에는 다시 시작한다.

## 4. 기준이 바뀌었을 때

코드는 고치지 않는다. **YAML만 고친다.** 절차는 `.opencode/skills/update-blind-rules/SKILL.md`. 요약:

1. 주제를 더하거나 낱말을 고친다. 다른 낱말 안에 들어갈 수 있는 낱말은 `keywords`가 아니라 `patterns`로 쓴다.
2. `version`을 올린다.
3. `tests/test_blind.py`에 걸려야 하는 문장과 걸리면 안 되는 문장을 더하고 `pytest tests/test_blind.py`.
4. `/internal/v1/blind/check`로 현업이 준 예시 문장을 넣어 본다.
5. 이 문서의 1장 표와 맨 위 "기준 출처"를 고친다.

오탐을 막으려고 지금 넣어 둔 처리:

| 낱말 | 겹치는 말 | 처리 |
| --- | --- | --- |
| 여자 / 남자 | 참**여자** | 앞 글자가 한글이면 제외 |
| 성별 | 특**성별**로 | 앞 글자가 한글이면 제외 |
| 아내 | 알**아내**다 | 앞 글자가 한글이면 제외 |
| 재산 | 지식**재산**권 | 앞 글자가 한글이거나 뒤가 "권"이면 제외 |
| 자가 | 지원**자가** | "자가 주택/소유/에 거주"일 때만 |
| 전세 | **전세**계 | "전세로/에/집/살"일 때만 |
| 국적 | 다**국적** | 앞 글자가 한글이면 제외 |
| 가족 | **가족 같은** 분위기 | `allow` |

## 5. 한계

- 낱말·정규식 규칙이다. 돌려 말한 표현("댁에서는 뭐라고 하세요?", "주말에는 주로 누구와 보내세요?")은 잡지 못한다.
- 문장 단위로 가린다. 문장 부호가 없는 긴 글은 통째로 가려질 수 있다.
- 직무상 필요한 예외(예: 해외 근무 직무에서 체류 자격)는 표현할 수 없다.
- 오탐 가능성이 있는 낱말이 남아 있다: `형제`, `부동산`(부동산 서비스 프로젝트), `병력`, `노조` 등. 직무와 겹치면 `allow`나 `patterns`로 좁힌다.
- 금지 항목이 든 질문을 면접관이 **말로** 했는지는 검사하지 않는다(전사는 거르지 않는다). 필요하면 `transcript.final` 뒤에 `BlindFilter.check_text`를 불러 경고 이벤트를 내는 기능을 더할 수 있다(API 명세에 이벤트 추가 필요).
